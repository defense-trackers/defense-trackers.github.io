Methodology

How this data is collected, validated, and published — and, just as important, what it deliberately does not track.

What these are

Each tracker is a public dataset that consolidates information already scattered across government portals, registries, and announcements. The value is consolidation and a tamper-evident change history — not access to anything non-public.

How it works

  • Collection. A small Go engine fetches each source on a declared cadence using conditional requests (ETag / If-Modified-Since) and polite rate limits.
  • Normalization. Every source is reduced to a common record shape and written to data/<tracker>/current.json.
  • Change detection. Each run is diffed against the last published state; additions, removals, and changes are appended to events/<year>.jsonl.
  • Publication. The site is static — it simply renders the committed JSON. There is no server, no database, and no telemetry.

Freshness is stated, never assumed

Every source carries a state and a last-success timestamp in data/status.json, rendered as the signal light on each tracker:

  • fresh — updated within its cadence.
  • lagging — overdue; the last-good data is still shown, clearly marked.
  • stale / degraded — collection is failing; do not treat the data as current.

A failed fetch never overwrites good data with garbage. A validation gate quarantines suspicious batches (too few records, or implausible churn) and keeps the last-good snapshot live rather than publishing a broken one.

Verifiability

The changelog is append-only and hash-chained: each event records the SHA-256 of the previous event, so any edit to history is detectable. Anyone can re-derive the chain from the public data with the engine: engine verify --out .

What we deliberately do not track

These trackers cover solicitations, policies, authorizations, and public lists. They do not aggregate operational incidents, unit information, troop or platform movements, or anything that would assemble a sensitive picture from individually public pieces. That line is a design constraint on source selection, not an afterthought.
